# Промпт для агента: сделать веб-резюме по шаблону

Скопируй всё, что ниже строки `---`, в новый чат с агентом (Claude Code) вместе с папкой шаблона.

---

Ты делаешь персональное веб-резюме (одностраничный сайт) по готовому шаблону.
Шаблон лежит в текущей папке — это статика без фреймворков и без сборки: `index.html` + `content.js` + движок `assets/js/app.js` + `assets/css/styles.css`.

## Что уже есть в шаблоне

```
index.html              # оболочка + SEO/OG/JSON-LD, плейсхолдеры {{...}}
content.js              # ← ВЕСЬ контент резюме (скелет, который ты заполняешь)
content.example.js      # заполненный пример другого человека — образец тона и структуры
assets/js/app.js        # движок: рендер, переключатель RU/EN, аккордеоны, лайтбокс
assets/css/styles.css   # оформление, акцентный цвет берётся из settings.accent
build-media.js          # node build-media.js → пересобирает media-index.js из папок media/
media-index.js          # авто-генерируемый индекс медиа, руками не трогать
build-cv.example.py     # генератор PDF-резюме на reportlab (данные захардкожены — переписать)
media/                  # фото/видео по папкам-разделам
robots.txt, sitemap.xml # SEO
.claude/launch.json     # локальный просмотр: python3 -m http.server 8124
```

Архитектурные правила, которые нельзя нарушать:
- **Никаких фреймворков и сборки.** Сайт должен открываться двойным кликом по `index.html` (протокол `file://`) и работать.
- **Весь контент — только в `content.js`.** Движок и стили правим лишь если человек хочет другой внешний вид.
- Каждая строка текста — объект `{ ru: "...", en: "..." }`. Оба языка обязательны; пустая строка допустима.
- Медиа не перечисляются в `content.js` — у раздела указывается `mediaDir`, а файлы подхватывает `node build-media.js`.

## Порядок работы

1. **Собери данные о человеке.** Задавай вопросы пачками, не по одному. Нужно:
   - имя (RU и EN), должность/роль, город и страна, e-mail, Telegram/LinkedIn/GitHub/сайт;
   - слоган в одну строку и абзац «о себе»;
   - 2–4 цифры для блока `stats` (годы опыта, размер команды, число проектов…);
   - места работы: компания, ссылка, роль, локация, период, краткое описание, 3–8 пунктов достижений (часть пометить `key: true`), список навыков;
   - проекты: название, период, ссылка, описание, навыки;
   - навыки по группам, образование, курсы, языки;
   - акцентный цвет и язык по умолчанию.
   Если человек присылает старое резюме (PDF/docx/LinkedIn) — вытащи всё оттуда сам и переспроси только пробелы.

2. **Заполни `content.js`.** Тон: конкретика и глаголы прошедшего времени, цифры вместо оценок («вырастил команду с 4 до 11»), без канцелярита и без хвалебных прилагательных. Английская версия — не подстрочник, а нормальный английский. Ориентир — `content.example.js`.

3. **Замени плейсхолдеры `{{...}}`** в `index.html` (title, description, OG, Twitter-card, JSON-LD Person, noscript-блок), а также домен в `sitemap.xml` и `robots.txt`. Плейсхолдеры: `{{FULL_NAME}}`, `{{FULL_NAME_RU}}`, `{{FIRST_NAME}}`, `{{LAST_NAME}}`, `{{ROLE}}`, `{{SHORT_BIO}}`, `{{DOMAIN}}`, `{{EMAIL}}`, `{{CITY}}`, `{{COUNTRY}}`, `{{COUNTRY_CODE}}`, `{{LINKEDIN_URL}}`, `{{TELEGRAM_URL}}`. Проверь `grep -rn "{{" .` — не должно остаться ни одного.

4. **Медиа.** Под каждое место работы и проект заведи папку `media/experience/<slug>/` или `media/projects/<slug>/`, положи туда файлы с числовым префиксом (`01-…`, `02-…`), подписи — в `captions.json`, внешние ссылки (YouTube/Vimeo/Google Drive) — построчно в `links.txt` (формат `ССЫЛКА | подпись_RU | подпись_EN`). Затем `node build-media.js`. Портрет — `media/portrait.jpg` и кадрированный кружок `media/portrait-avatar.jpg`.

5. **Фавиконки.** Сгенерируй из круглого портрета набор PNG в `assets/img/` (16, 32, 48, 180, 192, 512 + `apple-touch-icon.png`) и `favicon.ico` в корне — в шаблоне их нет, `index.html` на них уже ссылается. Подойдёт ImageMagick.

6. **Проверь локально:** `python3 -m http.server 8124`, открой страницу, прощёлкай переключатель RU/EN, аккордеоны опыта, лайтбокс с медиа, мобильную ширину. Убедись, что консоль браузера чистая.

7. **PDF-резюме (опционально).** `build-cv.example.py` — рабочий генератор на `reportlab`, но с захардкоженными данными предыдущего владельца. Скопируй в `build-cv.py` и перепиши константы (`OUT`, `PORTRAIT`, `NAME`, `CONTACT`, `ABOUT`, блоки опыта) под нового человека. Проверь: PDF должен помещаться в 1–2 страницы.

8. **Публикация.** Это статика — Netlify / Vercel / GitHub Pages / Cloudflare Pages, либо свой nginx на VPS с сертификатом Let's Encrypt под личный домен. Спроси, что человеку ближе, и доведи до живого HTTPS-адреса; после деплоя проверь превью ссылки в Telegram/LinkedIn (OG-картинка `media/portrait.jpg` должна быть доступна по абсолютному URL).

9. **Обнови `README.md`** под нового владельца и оставь короткую инструкцию «как самому дописать место работы и приложить фото» — человек должен уметь обновлять резюме без агента.

## Чего не делать
- Не добавлять сборщики, npm-зависимости, React и т.п.
- Не размазывать контент по HTML — он живёт в `content.js`.
- Не выдумывать факты, цифры и достижения: если данных нет — спроси.
- Не оставлять в репозитории материалы предыдущего владельца (`content.example.js` и `build-cv.example.py` удали, когда закончишь).
